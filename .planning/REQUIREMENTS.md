# Requirements: Инструмент расчета рентабельности по требованиям YouTrack

**Defined:** 2026-04-05
**Core Value:** Позволять в моменте понять, остается ли требование прибыльным и сколько денег нужно дополнительно согласовать с заказчиком для выхода на целевую рентабельность.

## v1 Requirements

### YouTrack Scope

- [x] **YTSC-01**: Пользователь может ввести ID родительской задачи YouTrack и запустить расчет по одному требованию.
- [x] **YTSC-02**: Система определяет поддерживаемую иерархию задач для расчета и рекурсивно обходит все вложенные задачи до нижнего уровня.
- [x] **YTSC-03**: Система либо показывает полное дерево поддерживаемой иерархии, либо блокирует результат с явной ошибкой, если root issue недоступна или хотя бы часть поддерживаемого дерева недоступна текущему пользователю.
- [x] **YTSC-04**: Система позволяет вручную обновить данные из YouTrack перед пересчетом и показывает момент последней синхронизации.

### Worklogs

- [x] **WORK-01**: Система собирает фактически затраченное время по всем включенным задачам в иерархии требования.
- [x] **WORK-02**: Система корректно агрегирует трудозатраты по иерархии без двойного учета задач и worklog-записей.
- [x] **WORK-03**: Система сохраняет расчет в состоянии ошибки или частичного покрытия, если не удалось получить все обязательные данные для достоверного подсчета.

### Cost Allocation

- [x] **COST-01**: Система относит фактические трудозатраты к направлениям `devops`, `backend`, `analytics`, `frontend`, `mobiledev`, `qa`, `design`, `pm` по роли исполнителя.
- [x] **COST-02**: Система показывает трудозатраты и себестоимость как по требованию целиком, так и по каждому направлению отдельно.
- [x] **COST-03**: Система явно помечает пользователей или трудозатраты, которые не удалось отнести ни к одному направлению.
- [x] **COST-04**: Система рассчитывает себестоимость на основе настраиваемых ставок по направлениям или ролям, используемых в расчете.

### Budgets

- [ ] **BUDG-01**: Пользователь может вручную задать бюджет по каждому направлению перед расчетом.
- [ ] **BUDG-02**: Пользователь может в любой момент скорректировать бюджет по каждому направлению и сразу получить обновленный расчет.
- [ ] **BUDG-03**: Система сохраняет исходный согласованный бюджет отдельно от пользовательских изменений сценария пересчета.

### Profitability

- [x] **PROF-01**: Система рассчитывает рентабельность по формуле `(бюджет - затраты) / бюджет * 100%`.
- [x] **PROF-02**: Система показывает фактическую рентабельность по требованию целиком.
- [x] **PROF-03**: Система показывает рентабельность по каждому направлению отдельно.
- [x] **PROF-04**: Система показывает денежные значения бюджета, затрат и отклонения вместе с процентом рентабельности.
- [x] **PROF-05**: Если рентабельность ниже 20%, система показывает сумму, которую нужно дополнительно согласовать с заказчиком для достижения целевой рентабельности 20%.
- [x] **PROF-06**: Если бюджет отсутствует или некорректен для расчета, система не показывает ложный процент и объясняет, что нужно исправить.

### Reforecast

- [ ] **REFO-01**: Пользователь может указать дополнительные часы по выбранному направлению для запроса на увеличение оценки.
- [ ] **REFO-02**: Система пересчитывает прогнозные затраты и прогнозную рентабельность с учетом дополнительных часов без изменения фактических трудозатрат.
- [ ] **REFO-03**: Система показывает одновременно текущую фактическую рентабельность и новую прогнозную рентабельность после добавления дополнительных часов.
- [ ] **REFO-04**: Система позволяет в одном сценарии добавить дополнительные часы по нескольким направлениям.

### Interface

- [ ] **UI-01**: Пользователь видит итоговую карточку требования с ключевыми метриками: бюджет, затраты, фактическая рентабельность, прогнозная рентабельность и недостающая сумма до целевых 20%.
- [ ] **UI-02**: Пользователь видит таблицу с разбивкой по направлениям, где для каждого направления показаны бюджет, фактические часы, дополнительные часы, затраты и рентабельность.
- [ ] **UI-03**: Система подсвечивает рентабельность красным цветом, если она ниже 20%, и зеленым, если она не ниже 20%.
- [ ] **UI-04**: Пользователь может быстро понять, на каких направлениях возник перерасход и какой вклад они дают в итоговую рентабельность.

### Auditability

- [ ] **AUDT-01**: Система разделяет импортированные данные YouTrack и пользовательские сценарные изменения так, чтобы можно было объяснить происхождение расчета.
- [ ] **AUDT-02**: Система хранит метаданные расчета: какой root issue был рассчитан, когда были обновлены данные YouTrack и какие бюджеты/дополнительные часы использовались.

## v2 Requirements

### Explainability

- **EXPL-01**: Пользователь может провалиться от общего итога до конкретных задач и worklog-записей, повлиявших на себестоимость.
- **EXPL-02**: Система показывает отдельные диагностические причины неполного расчета: скрытые задачи, недоступные worklogs, неподдерживаемые связи, unmapped роли.

### History

- **HIST-01**: Пользователь может сохранять и открывать несколько снимков пересчета по одному требованию.
- **HIST-02**: Система показывает историю изменения бюджетов и сценариев дополнительных часов.

### Operations

- **OPER-01**: Система поддерживает SSO для внутреннего доступа сотрудников.
- **OPER-02**: Система выполняет тяжелые синхронизации YouTrack в фоне, если объем данных не укладывается в быстрый пользовательский запрос.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Расчет нескольких требований одновременно | v1 должен решать один основной сценарий PM без усложнения интерфейса и модели хранения |
| Портфельные дашборды по проектам и клиентам | Это отдельный аналитический продукт, не нужный для проверки одного запроса на увеличение оценки |
| Полноценный PSA-функционал: инвойсы, выручка, capacity planning, контракты | Слишком далеко от ядра задачи по рентабельности требования |
| Пользовательская настройка формулы рентабельности и целевого порога | В текущем бизнес-процессе формула и целевая норма 20% уже зафиксированы |
| Ручная классификация каждой worklog-записи по направлению | Это превратит продукт в инструмент постоянной ручной чистки данных вместо автоматизации |
