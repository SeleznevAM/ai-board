## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon gaps, compact helper spacing inside task cards |
| sm | 8px | Label-to-input spacing, metric label/value separation |
| md | 16px | Default control padding, row gaps, task-card internal spacing |
| lg | 24px | Section padding, summary card padding, panel padding |
| xl | 32px | Vertical gap between major workspace sections |
| 2xl | 48px | Page padding top/bottom and major panel breathing room |
| 3xl | 64px | Maximum page-level separation between workspace blocks on wide layouts |

Exceptions: `44px` minimum tap height for task-card numeric inputs and commit/reset buttons when they are the primary interactive controls for scenario editing.

Layout rules:
- Keep the main workspace as one centered column up to `980px` wide.
- Use `32px` vertical separation between root sections: lookup, budget, scope tree, summary, breakdown, state panels.
- Inside any card that mixes fact and forecast, separate the two groups with at least `16px` and a visible border or background shift; never rely on color alone.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f7efe2` | Page background, broad workspace surface, default canvas tone |
| Secondary (30%) | `#fffaf2` | Cards, nested panels, task-card backgrounds, grouped fact/forecast blocks |
| Accent (10%) | `#6f4a16` | Refresh action, save/apply scenario actions, active scenario chips, YouTrack links |
| Destructive | `#9c1c1c` | Refresh-discard confirmation emphasis, blocked/error warnings, reset-scenario action only |

Accent reserved for: `Refresh snapshot`, `Save direction budgets`, `Apply extra hours`, active scenario badges, and links that leave the app for YouTrack. Do not use accent for every border, every label, or neutral table text.

Color rules:
- Fact values stay neutral on secondary surfaces; forecast values get accent emphasis only on the changed number, not the whole card.
- Profitability below `20%` uses destructive red; profitability at or above `20%` uses a success green derived in-code for implementation, but the contract reserves red/green strictly for margin status and not for generic decoration.
- Baseline versus scenario distinction must use structure first: side-by-side grouping, labels, and separators. Color is secondary.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Apply extra hours |
| Empty state heading | No scenario yet |
| Empty state body | Load a root issue, then add extra hours on task cards to see how forecast cost and profitability change before asking the client for more budget. |
| Error state | Scenario calculation is unavailable because the current YouTrack snapshot is incomplete or blocked. Refresh the requirement, fix blocked issues, then try the scenario again. |
| Destructive confirmation | Refresh snapshot: Refreshing from YouTrack will discard all unsaved scenario hours on this screen. Continue? |

Additional copy rules:
- Root issue refresh button keeps the existing label `Refresh snapshot`.
- Budget editing stays noun-first and operational: `Total budget`, `Edit direction budgets`, `Save direction budgets`.
- Task-card scenario control labels must be explicit: `Extra hours`, `Apply extra hours`, `Clear scenario`.
- Provenance text must name the data source directly: `Actual from YouTrack`, `Forecast from scenario`, `Last sync`, `Root issue`.
- If no scenario hours are applied yet, show a neutral helper sentence instead of zero-heavy UI: `No extra hours added yet. Current values match the YouTrack snapshot.`

## Interaction Contract

### Page structure

1. Keep the existing page flow: header, root issue lookup, assignee directory entry point, budget section, scope tree, summary metrics, direction breakdown, state messages.
2. Add scenario editing inside task cards in the existing scope tree instead of creating a separate drawer, modal, or alternate tree.
3. Show factual and forecast values simultaneously in summary and direction breakdown once any scenario edit exists.

### Scenario input on task cards

- Place the extra-hours control below assignee/provenance text and above the external YouTrack link.
- Use a single numeric input plus two explicit actions: `Apply extra hours` and `Clear scenario`.
- Input accepts positive decimal hours only.
- The committed source of truth is page-level scenario state, not per-card local-only state.
- After apply, show a compact confirmation line on that same card: `+{hours} h in scenario` and, when pricing is known, the derived added cost.

### Fact versus forecast presentation

- Summary cards must show `Current` and `Forecast` as separate labeled groups, not merged sentences.
- The first changed metric in the summary must be `Cost`, followed by `Profitability`, followed by `Needed to reach 20%`.
- Direction breakdown rows must include `Actual hours`, `Extra hours`, `Forecast cost`, and `Forecast profitability` once a scenario exists.
- If a direction has no scenario impact, keep the row visible and show `0.00` extra hours rather than hiding it.

### Refresh discard guard

- Trigger confirmation only when the user submits a new refresh while scenario edits are dirty.
- Do not warn on ordinary typing, card edits, or page navigation in this phase.
- Confirmation copy is fixed by the copy contract above.
- If the user cancels, preserve the current scenario state without side effects.

### Provenance and auditability

- Every screen with scenario values must expose `Root issue` and `Last sync`.
- Scenario-specific numbers must be labeled as forecast, never presented as actual.
- The interface must make it visually clear that YouTrack data is immutable in this phase and scenario changes are local to the current screen session.
