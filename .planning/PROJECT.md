# Инструмент расчета рентабельности по требованиям YouTrack

## What This Is

Веб-приложение для менеджеров проектов, которое автоматически считает рентабельность по требованию или группе задач в YouTrack. Пользователь вводит идентификатор родительской задачи, корректирует бюджет по направлениям, а система рекурсивно собирает фактические трудозатраты по всем вложенным задачам, переводит их в затраты по ставкам и показывает текущую и прогнозную рентабельность.

## Core Value

Позволять в моменте понять, остается ли требование прибыльным и сколько денег нужно дополнительно согласовать с заказчиком для выхода на целевую рентабельность.

### Active

- [ ] Пользователь может ввести ID родительской задачи YouTrack и получить расчет по всей иерархии вложенных задач.
- [ ] Пользователь может задать и в любой момент скорректировать бюджет по направлениям `devops`, `backend`, `analytics`, `frontend`, `mobiledev`, `qa`, `design`, `pm`.
- [ ] Система показывает фактическую и прогнозную рентабельность по требованию целиком и по каждому направлению, включая перерасчет при запросе дополнительных часов.
- [ ] Система подсвечивает рентабельность ниже 20% красным цветом, а 20% и выше зеленым.
- [ ] Система показывает сумму, которую нужно дополнительно согласовать с заказчиком, если рентабельность упала ниже целевых 20%.

### Out of Scope

- Работа с несколькими требованиями одновременно — для v1 нужен расчет одного требования за раз, чтобы не раздувать интерфейс и сценарии хранения.
- Управление составом пользователей и ролями доступа — круг пользователей будет определен позже, это не критично для первого релиза.
- Отдельное сценарное моделирование без привязки к реальному запросу на увеличение оценки — в v1 нужен именно оперативный перерасчет в текущем процессе.

## Context

Сейчас рентабельность по требованию считается вручную: менеджер собирает трудозатраты по задачам из YouTrack, переносит их в таблицу или считает на калькуляторе, умножает часы на ставки и сравнивает с бюджетом из сметы. Основная проблема — это высокая трудоемкость ручного сбора, заметный риск ошибки из-за человеческого фактора и отсутствие быстрого ответа в момент, когда команда запрашивает увеличение оценки по уже запущенному проекту.

Источник фактических данных — YouTrack. Структура работы иерархическая: есть родительские требования или группы задач, внутри которых могут быть обычные задачи, подзадачи и вложенные группы задач с несколькими уровнями вложенности. Для расчета нужно обходить дерево задач до нижнего уровня и суммировать фактические трудозатраты.

Разнесение затрат по направлениям должно происходить по роли исполнителя, которая хранится в системе. Формула рентабельности зафиксирована: `(бюджет - затраты) / бюджет * 100%`.

## Constraints

- **Integration**: YouTrack является обязательным источником фактических трудозатрат — без корректной интеграции продукт не решает основную задачу.
- **Product Scope**: Первая версия работает с одним требованием за раз — это ограничивает сложность интерфейса и ускоряет вывод MVP.
- **Domain Logic**: Целевая рентабельность равна 20% — от этого порога зависят цветовая индикация и расчет недостающей суммы согласования.
- **Budget Model**: Бюджет по направлениям редактируется вручную в интерфейсе — система должна поддерживать корректировки в любой момент времени.
- **Role Mapping**: Классификация затрат по направлениям строится на поле роли исполнителя — качество результата зависит от консистентности ролей в YouTrack.

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Веб-приложение как формат v1 | Нужен удобный интерфейс в браузере для оперативного использования менеджером | — Pending |
| Один расчет на одно требование | Главный сценарий — быстро проверить конкретное требование при запросе на увеличение оценки | — Pending |
| Распределение трудозатрат по роли исполнителя | В системе уже есть исполнитель и его роль, это снижает объем ручной классификации | — Pending |
